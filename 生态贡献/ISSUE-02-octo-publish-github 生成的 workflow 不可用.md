# ISSUE-02 · `octo publish-github` 生成的发布 workflow，用了 `hub` 里不存在的子命令

**上报对象**：`octo`（OctoScript 工具链，生成器 `publish-github`）+ 与 `hub` 的接口约定
**核实时的 app-hub 提交**：`a15580cbdcc734bd6387ad89f43e371a5155c321`
**严重度**：**高**（会在**打 tag 的瞬间**触发一条必然失败的发布流水线，而 `PUBLISHING.md` 又要求公开发布必须打 tag）
**状态**：未修复，本轮已按要求**不提交**该 workflow 并留存证据

---

## 一句话

`octo publish-github` 会往仓库里写一个 `.github/workflows/publish-app.yml`，它调用 `hub publisher-prepare / publisher-attach / publisher-verify / publisher-pack` 四个子命令来构建、签封、打包应用。**本机的 `hub` 二进制没有这四个子命令**；同时官方 `docs/PUBLISHING.md` 明确写着这套东西「还不存在，不要加」。于是：**工具让你生成、生成物自己跑不起来、文档让你别用**——三处互相矛盾。

---

## 复现步骤

### 1. 生成的 workflow 里调用了四个子命令

```bash
$ grep -n "publisher-" .github/workflows/publish-app.yml
tools/app-hub/target/release/hub publisher-prepare app/my-entry/morning-brief/bundle ...
"$RUNNER_TEMP/prepared/hub" publisher-attach "$RUNNER_TEMP/prepared/bundle" --attestation "$ATTESTATION_PATH"
"$RUNNER_TEMP/prepared/hub" publisher-verify "$RUNNER_TEMP/prepared/bundle"
"$RUNNER_TEMP/prepared/hub" publisher-pack "$RUNNER_TEMP/prepared/bundle" --out "$RUNNER_TEMP/prepared/morning-brief.pack.json"
```

文件头自述来源：

```
# Generated by tools/octo publish-github. No publisher signing secret is needed.
# Push a new v<manifest.version> tag after reviewing the app and screenshots.
on:
  push:
    tags: ['v*']
```

### 2. `hub` 根本没有这些子命令

```bash
$ hub --help
hub — the OctoSense app hub command (ADR 0003)

  hub keygen <path>                     make a signing key, print its public half
  hub pubkey <key file>                 print a key's public half
  hub certify --anchor <f> --working <f>   anchor certifies a working key
  hub stamp <bundle>                    write the bundle's digest into its manifest
  hub sign-manifest <bundle> --key <f> --key-id <id>
  hub check <bundle> [--catalog <f>] [--allow-unsigned] [--publisher-key id=hex]
  hub publish <bundle> --catalog <f> --key <f> --anchor-cert <hex>
              --publisher <id> [--repo <url>] [--commit <sha>] [--out <dir>]
  hub withdraw <app> --version <v> --reason <text> --catalog <f> --key <f> --anchor-cert <hex>
  hub remove <app> [--version <v>] --catalog <f> --key <f> --anchor-cert <hex> [--out <dir>]
  hub scan <bundle> [--reviewer <cmd>] [--packet <out.json>]
  hub verify <catalog> --anchor <hex>
```

`publisher-*` 一个都不在。

### 3. 生成物还会硬编码一条本仓库并不存在的路径

workflow 里写死 `app/my-entry/morning-brief/bundle`。`octo` 把仓库检出到 `path: app`，于是完整路径是 `app/app/my-entry/morning-brief/bundle`——多了一层 `app`。第 2 步里 `prepare` 那一条因此会以「找不到 bundle」失败，比子命令缺失更早炸。

### 4. 官方文档明令不要加这条 workflow

`OctoSense-App-Hub/docs/PUBLISHING.md`（上引提交）「Submitting」一节：

> **Not yet available.** There is no separate index repository and no `octosense-org/publish-app` GitHub action. **Do not add a release workflow that uses them.** When they exist, this section will say so and give the workflow.

`PUBLISHING.md` 同时把当下唯一被接受的路线写得很清楚：推送签名 bundle → 打 tag → 在 App-Hub 仓库**开 issue**（`Submit <app id> <version>`），由维护者跑 `hub check` / `hub scan` 后再 `hub publish`。

---

## 危害

1. **静默埋雷**：生成是「顺手」发生的，作者往往不知道仓库里多了这个文件；等到打 `v*` tag 那一刻才炸，而那一刻通常正是**提交截止前**。
2. **失败信息会误导**：报错是「找不到 bundle 路径」，于是作者第一反应是改路径、改 CI，而真正的问题是这个 workflow 整个不该存在。
3. **两处权威互相打架**：工具（可执行、会写文件）说要用，文档（唯一被接受的提交方式）说别用。在没有更强信号时，作者会信工具。

---

## 修复建议

1. **`octo publish-github`：在 index 仓库与 `octosense-org/publish-app` 落地之前不要生成任何 workflow。** 若确实需要保留该命令，让它**只打印路线说明**（打 tag + 开 issue 的步骤），而不是写文件。
2. 若必须生成，至少让生成物**只调用 `hub` 真实拥有的子命令**（上面的 `--help` 列表），并在生成前做一次 `hub --help` 能力探测，探测不到就拒绝生成并打印原因。
3. **路径拼接修一下**：生成器应按「仓库根的相对路径」写 bundle 路径，而不是把检出目录名再拼一遍；同时尊重「bundle 不在仓库根」的布局（一个仓库放多个 entry 的 monorepo 很常见）。
4. 建议在 `hub check` 或一个独立的 `octo doctor` 里加一条：**仓库里若存在 `.github/workflows/*.yml` 且引用了 `publisher-*`，报 warning 并指向 `PUBLISHING.md` 的这一段**。这样作者在打 tag 之前就能看见。
5. 文档侧顺带补一句：**`.github/workflows/publish-app.yml` 不应被提交**，建议加进 `octo` 生成的 `.gitignore`。

## 本轮应用的绕过方式（可复核）

- **不提交** `.github/workflows/publish-app.yml`（至今仍是 untracked 状态，见仓库 `git status`）。
- 发布改走文档给的路线：本地 `hub stamp` → 截图 → 再 `hub stamp` → `hub check --allow-unsigned` → `hub scan`，然后**打 tag + 开 issue** 提交，由维护者复核。
- 证据文件：`.github/workflows/publish-app.yml`（原样保留，未修改内容，仅不提交）。
