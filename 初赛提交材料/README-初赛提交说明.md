## 一、作品一句话

**打开一张卡片，AI 抓取当天科技新闻，由「AI 编辑部」挑重点，由「视觉主编」现做一张头版，并且有一位常驻主编听你说话、替你操作整个程序。**

产品的内核不是"AI 帮你读新闻"，而是 ——
**一个会记住你读过什么、会押注、会拒绝出报、会认错、也把过程摊开的编辑部。**

## 三、启动说明

### 3.1 作品形态

**OctoSense App Hub 卡片包**（OctoScript 应用）。

**权威位置**：`my-entry/morning-brief/bundle/`（这是被 `hub check` 校验、被宿主加载的那一份）
**本文件夹的副本**：`初赛提交材料/bundle/`（内容与上面完全一致，方便单独取用）

| 文件 | 说明 |
| --- | --- |
| `main.splash` | 唯一的程序文件（OctoScript / splash 脚本，约 4800 行） |
| `manifest.json` | 清单：id / 版本 / 能力 / 网络白名单 / bundle 摘要 |
| `listing.json` | 上架信息：副标题 / 描述 / 关键词 / 截图 / 发布者 |
| `assets/icon.svg` | 图标 |
| `screenshots/` | 4 张实机捕获的截图 |

### 3.2 运行环境

| 项 | 值 |
| --- | --- |
| 宿主 | OctoSense App Hub `card-host`（含 `llm` 服务），官方仓库提交 `46d67e5` |
| 开发流程工具 | `OctoScript-App-Design-Flow`（提供 `tools/octo`） |
| 平台 | Windows（本机实测） |
| 依赖 | 宿主提供的 `llm` 服务（大模型 + 画图能力）；**语音能力需宿主补丁**（见 3.3） |

> ⚠️ 官方运行环境不在本仓库内（官方仓库需单独获取）。
> 下载地址与国内镜像命令见仓库 `07_官方仓库下载说明.md`。

### 3.2.1 语音能力的宿主依赖（重要）

作品的「主编说话 / 分段朗读 / 麦克风对话」需要宿主新增三个方法
（`llm.speak` / `llm.speaking` / `llm.listen_*`）。官方的 `card-host` 默认没有它们。

- **补丁位置**：`my-entry/patches/`（`host-voice.patch` + `host-voice-card-host.patch` + 说明）
- **打补丁**：`cd <你的 OctoSense-App-Hub> && git apply <本仓库>/my-entry/patches/host-voice.patch`，然后重建 `card-host`
- **不打补丁也不会崩**：应用启动时会探测宿主能力（`llm.speech`）。
  没有语音能力时，**应用自动降级为纯键盘交互**，其余全部功能（取数、编辑部、头版、阅读页）不受影响。
  这也是一处对「宿主能力缺失」的失败处理。

### 3.3 启动步骤

```powershell
# 1) 预检：包摘要 + 规范检查
hub stamp my-entry\morning-brief\bundle
hub check my-entry\morning-brief\bundle --allow-unsigned    # 期望 PASSED

# 2) 启动卡片（通过官方 octo 工具）
python <OctoScript-App-Design-Flow>\tools\octo run `
    my-entry\morning-brief\bundle `
    --port 8136 --detach `
    --app-data <一个可写的状态目录>

# 3) 退出
curl -s 127.0.0.1:8136/quit
```

## 四、数据来源与限制（对照官方要求第 4 条）

### 4.1 数据来源

| 来源 | 域名 | 内容 | 性质 |
| --- | --- | --- | --- |
| Hacker News（Algolia API） | `hn.algolia.com` | 首页热榜 30 条 | 公开 API |
| TechMeme | `www.techmeme.com` | 最新条目 RSS | 公开订阅源 |

作品**只聚合标题与摘要**，不做正文抓取与全文转载；每条都保留原文链接。

### 4.2 申请的能力（`manifest.json` 可核验）

| 能力 | 用途 |
| --- | --- |
| `net` | 只访问上面两个域名（白名单） |
| `images` | 显示新闻自带的缩略图 |
| `storage` | 把每一期晨报、头版、留痕存到本机沙箱 |
| `llm` | 主编挑选 / 编辑部评审 / 画头版 / 语音（由宿主代理调用） |

> 规范要求「只申请屏幕上真正需要的」。我们删掉了未使用的 `web` 能力。

### 4.3 授权与拒绝的行为

- **先授权、再取数**：点「生成晨报」后先出**取数计划**（访问哪些域名、抓多少条、怎么筛），
  用户点「批准并取数」之后才发起网络请求；点「暂不」则**不发起任何网络请求**。
- 应用**不收集、不上传**任何个人信息，不需要登录、不索取密码。
- 所有数据存在本机沙箱；卸载即删除。详见仓库 `PRIVACY.md`。

### 4.4 失败与空状态的行为

| 情况 | 行为 |
| --- | --- |
| 部分来源失败 | 只展示成功的来源，并**列出失败项**，绝不补齐条数 |
| 全部来源失败 | 保留上一次成功的结果并标注已过期 |
| 筛选零命中 | 明确说明这是筛选结果，而不是获取失败 |
| 信源太薄 | 主编出「今日休刊」（拒刊），读者可一键否决 |

演示视频 2:26–2:40 段就是**「暂不」的取消状态**。

## 六、Agent 任务演示（对照官方要求第 5 条）

**输入**：一句话意图（或勾选主题 + 条数上限）。

**Agent 实际完成的步骤**（视频里逐段可见）：

1. **出报前先问一句** —— 主编问「今天更想看哪个角度」，给两个互斥选项
2. **写取数计划** —— 列出将访问的域名、条数上限、判断方式（**不联网**）
3. **用户授权** —— 点「批准并取数」才联网
4. **取数** —— 官方 `net` 能力抓两个公开来源
5. **信源评级** —— 每条标成一手 / 二手 / 传闻 / 转载
6. **三视角编辑部** —— 技术 / 行业 / 读者三个角度**背靠背独立评审**（互相看不到对方）
7. **主编终审** —— 挑重点、写理由、公开砍掉的三条
8. **视觉主编做头版** —— 按当天头条现画横图 + 英文标语
9. **落盘** —— 整期存到本机，含出报链路留痕（谁在什么时候说了什么）

**如何核验**：
- 结果页公开**淘汰率**（45 条里见报 10 条）与**信源构成**（一手 1 / 二手 7 / 转载 8）
- 每条都能看到来源、时间、热度、原文链接，以及**哪位编辑推荐了它**
- 阅读页有「AI 解读」「本报追过的线索」「这条消息的出处」

**哪些环节需要人工确认**：
- **联网取数必须用户明确批准**（这是硬闸门，代码里实现，不是提示词约定）
- 头版不满意可「换一张头版」；配图可「重画」

## 七、这个作品和同类有什么不同

| 常见做法 | 晨报卡 |
| --- | --- |
| AI 帮你读新闻 | AI 编辑部**互相看不见地**评审，主编终审并**公开取舍** |
| 尽量笃定 | 追求**诚实**：拒刊、公开落选、更正上期错误、信源评级 |
| 黑盒输出 | **把出报过程摊开**：淘汰率、信源构成、留痕可回放 |
| 一次性输出 | 有**记忆**：读者画像、线索时间轴、预测对账 |

## 八、已知限制

- 只在 **Windows** 上实机验证过（`listing.json` 的 `platforms` 已如实只写 windows）
- 运行依赖宿主提供的 `llm` 服务（本机演示走了一个临时的转发线路，见交接文档）
- 新闻只覆盖 Hacker News 与 TechMeme 两个英文来源
- 头版与配图由宿主画图能力生成，质量受模型影响
