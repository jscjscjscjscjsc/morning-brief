## 三、白屏的机制（这一轮最值钱的发现）

用户说的「用着用着白屏、只有重开才行」，机制是这个：

1. splash 里访问**不存在的字段是报错**，不是返回空值：
   `property missing_field not found in prototype chain. Did you mean: …`
2. 列表渲染走 `on_render` 闭包。**闭包一抛错，那一整个区块的输出被丢弃**——
   界面就是「用着用着一片白」，日志里只有一行 `on_render closure failed; discarding its output`。
3. 什么时候会碰到不存在的字段？**回看往期**。行是从 `issues.json` 反序列化回来的，
   字段集合和当时的 `picked` 不完全一致（早期版本存的行少字段），
   于是「翻了两次往期 → 列表空白」。

这一轮加了两道防护：
- `row_meta` 改成 `r["source"]` + nil 判定（渲染路径上所有裸字段访问都过一遍）
- 新增 `issue_rows_safe()`：存档行读出来先做形状归一，把渲染会用到的字段
  （id/title/url/link/source/summary/image/tier/published）一次补齐，
  补的是空值不是假数据

另外还发现并修了一个**按钮被挡**的可用性问题：底部工具条的「记忆」标签是
`width: Fill`，把麦克风一直顶到最左边，正好压住计划页的「批准并取数」——
实测点不到。改成 Fit 宽度 + 决策页（计划/问询/拒刊/已取消）收起麦克风胶囊。

## 四、声音怎么做到「一字不差」

桌面版桌宠：`edge-tts` 的 `zh-CN-XiaoyiNeural`，rate +15% / pitch +14Hz。
卡片唯一出声通道是宿主的 `model.speak`，而宿主只有 Windows 自带引擎
（本机最像人的是 Huihui，成熟女声，跟桌宠完全不是一个人）。

做法（宿主进程里没有 Python 运行时，所以桥是独立进程）：
```
卡片 model.speak{voice:"zh-CN-XiaoyiNeural"}
  → 宿主 voice.rs 识别出这是咕嘎的音色
    → voice/edge.rs：常驻子进程 tools/edge_tts_bridge.py，行 JSON 协议
      → 桥用 edge-tts 合成 → miniaudio 解码成 16-bit PCM → base64 回传
    → 宿主直接入播放队列（与系统引擎同一条队列）
  失败（没网/没装/超时）→ 静默落到系统引擎，卡片无感
```
细节：桥会把合成结果按 `(text,voice,rate,pitch)` 哈希缓存到临时目录；
edge-tts 直连偶发 TLS 重置，桥自动读 Windows 系统代理；
宿主最多容忍 2 次连续失败，之后整个会话不再尝试（避免每次都卡 20 秒）。

配套：`tools/launch.py` 启动时把桥的路径经 `GUGUA_VOICE_BRIDGE` 传给宿主。

## 五、涟漪为什么是「点击扩散环」而不是「鼠标追踪水波」

查过运行时源码：shader 能拿到全局时钟（`draw_pass.time`），但**脚本层拿不到指针位置、
也没有 set_uniform 接口**；运行时的 `glass.*` 套件（自带涟漪）不在受限 isolate 里注册。
所以「水波跟着鼠标走」在卡片里做不到。

能做且观感成立的是：点击瞬间在对应高度亮起一圈金色扩散环（0.85 秒摊开消失）。
用它覆盖主要交互点，手感是「指尖落到纸面上」。这是运行时的边界，已如实写进已知限制。
