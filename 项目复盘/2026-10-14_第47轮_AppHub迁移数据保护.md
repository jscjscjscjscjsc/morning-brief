# 第 47 轮 · 防止 App Hub 自动迁移误删应用数据

应用安装包已经放在 `.bundles/<id>/bundle`，但旧布局迁移代码仍在每次扫描时处理 `<id>/bundle` 等名称。应用只要把笔记存进自己的 `bundle/notes.txt`，下次扫描就可能丢失；全新安装也会触发，不需要经历升级。

## 这轮改了什么

修复官方 App Hub 基线 `386359153ed6377b5f047bd9ed2767a6a2ac2bc7` 的 `adopt_legacy_install`：已有非空现代安装目录时保留旧路径；没有现代安装时，用真实 manifest、应用 ID 和 BLAKE3 校验识别完整旧包，只移动选中的候选。未知数据、未发布下载、旧副本均保留，不按名称清理。对符号链接和 Windows junction/reparse point 做拒绝处理。

独立复核发现第一版修复会让“创建现代目录后、移动 bundle 前中断”的迁移无法重试。已补上严格为空的普通现代目录恢复路径，并加入回归；非空现代安装仍受保护。

交付物是可应用补丁、中文 ISSUE-10、真实前后日志、函数复核工具和本轮交接。官方 checkout 保持 ignored，没有嵌入作品仓库。旧补丁和别队贡献不计入本轮成果。

## 取舍与限制

旧迁移清理行为改为保留：残留的完整旧副本、半下载目录或损坏包可能继续占用磁盘，但不会仅凭名称删掉用户数据。损坏或摘要不匹配的旧安装需要显式修复，补丁不自动搬动。摘要用于识别迁移候选，运行时的目录准入、catalog 和签名验证仍由原有流程执行。

完整测试使用了本机现有 makepad/octoscript sibling checkout；依赖机制与官方 workspace 相同，revision 比精确 Git pins 旧，且 makepad 有未触碰的既有 `widgets/src/window.rs` 修改。Cargo 对四条依赖记录的环境调整已恢复，补丁不含 Cargo.lock。

本轮未运行 GUI、真实 shell 或 appstore 包套件，未做 Unix 平台验证，也不承诺抵御外部进程在检查与移动间主动竞争。未向官方上游发 issue/PR；当前授权交付范围是用户的 morning-brief 仓库。
