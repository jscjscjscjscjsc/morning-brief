# 第 46 轮：生态工具链三修

本轮把晨报卡开发依赖的 OctoSense / App Flow 工具链实际跑了一遍，新增三类可复现修复：发布配置写错层级仍报成功、Windows 默认编码和行尾破坏 UTF-8 文件、Windows 残留 Git worktree 注册无法恢复。

## 设计与实施依据

目标是提供固定版本、真实复现、最小补丁和前后证据。选择修工具链的直接根因；不自动重写我们的定制发布工作流，不把别队启动/桥接/日历 PR 算成自己的贡献。

1. 在 pinned 源码中建立真实 Git / UTF-8 文件回归，先确认失败原因。
2. 对发布增加最近 Git 边界检查；对文本显式 UTF-8 / LF；对 worktree 使用 NUL 路径记录和平台路径比较。
3. 独立审查修正 `new --system` 兼容性和 Python 3.9 测试 API 兼容性。
4. 导出包含回归的补丁，在干净 pinned 源码上应用并验证；提交报告、脚本和日志到自己的仓库。

两个官方 checkout 本来就被 `.gitignore` 排除，所以本轮交付可直接应用的 patch，避免只在本机改好了却没有提交修复。
