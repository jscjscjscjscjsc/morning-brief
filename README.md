# 晨报卡（morning-brief）— GoIM Agentic App 黑客松参赛作品

> 一句话：打开卡片，AI 自动抓取当天科技新闻、由「AI 编辑部」挑重点、「视觉主编」现做今日头版；
> 右下角有个常驻的 AI 主编，会听你说话、也会**公开押注并自己回来对账**。

## 现在能做到什么

> 第 1–24 条为第 45 轮及以前，均已在有宿主的机器上实机验证。
> **第 45 轮（2026-10-13）成图大改版**：整个界面换成「破晓」清晨纸色体系 + 顶部多日报页签
> （同时在手几期，切页不丢阅读位置）；咕嘎（智能体）整块并入新界面 —— 右下角桌宠、
> 三分区工作台（对话 / 干活 / 往期）、语音收音台、档案与收藏、浏览记录、读者画像、真伪核验台；
> 开场 CG 换成 **B 版《清晨印刷所》配乐版**（26 帧 / 6.8 秒，CG 里不出现桌宠）。
> 接手请看 `进度交接_第45轮后.md`。

1. 打开卡片先播 **6.8 秒开场 CG「B 版 · 清晨印刷所」**（26 帧纸页翻折动画，桌面版带配乐），随后自动恢复上次的日报与阅读位置
2. **常驻 AI 主编**：右下角站着一个纯代码画出来的小形象（会呼吸、会眨眼），旁边的「● AI 主编」展开对话条 —— 一句话让它操作整个程序：换主题、改条数、写关注点、生成计划、批准取数、取消、重新开始、打开某条、返回列表、前后条、换头版、画配图。界面上能点的，它都能做
3. 生成晨报：**主编先问一句二选一**（今天偏技术实现还是偏行业格局）→ 出**取数计划**请你批准 → 官方 net 能力抓 Hacker News + TechMeme → 信源评级 → AI 编辑部 3 个视角（技术 / 行业 / 读者）**背靠背独立评审** → 主编终审挑重点。**联网必须经你明确批准**（说过「批准」才放行，主编自己不能越过这一步）
4. 列表页：编号 + 来源缩略图 + 三方推荐标记 + AI 主编用时与 token 数
5. **今日头版**：深色 hero 卡片，按当天头条现画的横图 + 英文头版标语压在图上，点「换一张头版」可重画
6. 点进任意一条 → 卡片内阅读页：官方摘要 / AI 解读 / 更多报道 / 讨论 / 原文链接
7. **AI 配图**：阅读页顶部按标题现场生成配图，「重画」能换新图，缓存秒开
8. 全程能看到"编辑部交回几份意见、每个人用了多少秒"，不是黑盒
9. **语音对话**：点「🎙 说话」直接对主编讲话（中文识别）；点「念这一期」**分段朗读**整期（显示念到第几段，随时插话会停下，说「接着念」从断点继续）；主编答完话会自动配声音（可关）
10. **读者画像**：这份报记得你读过什么、常读哪些主题、你亲口说的偏好 —— 并且在主编选稿时真的用上
11. **本报记忆**：每一期的入选条目进本地档案；再读相关新闻时，页面会自动列出「本报追过这条线索」
12. **预测性晨报**：出报时主编公开押下 3 条「一周内可被事实检验」的判断，下一期取数后自动回访对账，说中 / 说错 / 还没到点都记在案，界面显示累计战绩 —— **主编为自己的判断负责**
13. **信源评级**：每条新闻按域名标注 **一手 / 二手 / 传闻 / 转载**，就写在卡片的元信息行里；候选名单带着等级进主编的提示词，传闻类最多入选 1 条且理由必须写明「尚未证实」
14. **拒刊权**：候选池里一手来源为 0、二手也只剩 2 条以内时，**主编拒刊** —— 出「今日休刊」页写明理由；同时给你一个「仍要出报」的按钮否决他
15. **工作量与信源构成公开**：报头下方一行「214 条里见报 10 条，淘汰率 95%」，再一行本期信源构成 —— 读者该知道编辑部到底看了多少、扔了多少
16. **采访草稿箱**：阅读页可请主编当场起草一封**只问一个问题**的追问邮件，存进本机 `outbox.json`。**发信不在这份程序里** —— 投递是外部动作，永远由你确认后自己发
17. **出报前的一问**：主编的问题会真的改变结果 —— 选中的那个角度就是本期的关注点，会进终审的提示词；可以语音答 A / B
18. **更正栏**：出报时把这一期报到的 3–5 条硬事实记进本机台账，**下一期取数后自动核对** —— 被新的消息推翻的说法就登进「更正」栏（写在结果页最上方），并累计进更正台账。**这是这份报第一次会认错**：它会押注、会拒刊，现在还会改口
19. **跨源矛盾检测**：把**同一天**的候选摆在一起互相校一遍。如果两条讲的是同一件事、关键数字或说法却对不上，就出「本报注意到口径不一致」卡 —— 两边原话并排摆着，主编写一句「**两个数字都在，我不替你选**」。别的产品在这个位置会选择"综合一下"，而它拒绝综合：不制造确定性
20. **线索时间轴**：归档时按信源成色记下这条消息**本报是从哪一步听到的**（爆料 / 跟进中 / 已确认）。下一期同一主题再出现时，界面会写「本报上次听到它时还只是「爆料」，今天到了「已确认」」—— 它记得一条消息的形状是会变的，不是每期拍一张快照
21. **落选公开**：主编砍掉没上的三条也列出来，每条附一句为什么没上（信源太薄 / 话题与已选重复 / 体量太小）。**取舍被看见，才能被反驳**
22. **出报链路可回放**：每出一期，编辑部把过程写进本机 `trail.json`（只留最近三期）—— 取了多少条原始、多少条进了候选池、**三位初审各自的原话**、主编终审的导语与每一条的入选理由。结果页新增一张「回放」卡。以前你只能问「你选了哪几条」，现在可以问「**你们是怎么选的**」。零额外大模型调用
23. **编辑部宪法**：9 处喂给模型的指令第一次被抽出来集中管理，每条带版本号与一句条款说明（`judge` 已到 v2）。版本号随出报一起落盘 —— 于是任何一期都能倒推回「它当时照着哪版规矩编的」，也为以后真做 A/B 留好了口子。**改文案就升版本号，不原地改**
24. **可被追问的两个新工具**：`read_trail`（读者问「你们是怎么选的」，主编调出当时的记录照实说，**提示词明令不许事后美化**）；`read_charter`（读者问「你们的标准是什么」，主编如实念出方针，**不许自己另编一套**）。工具数 **20 → 22** —— 这两个工具的共同点是：它们查的都是已经落盘的事实，不是模型现编的话

### 常驻 AI 主编的内部结构（四层）

| 层 | 实现 | 作用 |
| --- | --- | --- |
| 感知 | `ag_context()` | 把界面现状（在哪页、什么设置、入选了哪些条目、在读哪条、读者画像、信源构成、工作量、拒刊理由、你的提问与他的回答、朗读断点）讲给模型 |
| 决策 | `ag_turn()` / `ag_reply()` | 多轮工具调用循环，一轮最多六步，带重复调用拦截与未完成续推 |
| 工具 | `ag_tools` / `ag_do()` | 22 个工具，唯一派发入口，与界面按钮一一对应 |
| 界面 | `ag_dock` | 常驻对话条（气泡流 + 输入框 + 快捷短语 + 语音按钮） |

> **宿主补丁（两枚，见 `my-entry/patches/README.md`）**：
> `host-services.patch` 给官方 `OctoSense-App-Hub` 加 `model` / `llm`（语音）服务；
> `host-font-monospace-cjk.patch` 修官方 `makepad` 的等宽字体缺 CJK 兜底（不然页签中文是豆腐块）。
> 没打补丁的机器上卡片自动降级：没有 `model` 的宿主会拒收本包（见 `04_项目实操指南.md`），
> 只有字体没打时其余功能照常、等宽中文显示为方框。

## 快速开始（Windows）

**成员/评审要跑起来**（三步）：

1. 按 `07_官方仓库下载说明.md` 下好官方运行组件（`OctoScript-App-Design-Flow` + `OctoSense-App-Hub`）；
2. 按 `my-entry/patches/README.md` 打两枚宿主补丁并**重建 card-host**（认识 `model` 能力 + 等宽中文字体）；
   没重建过宿主的老二进制会把本包以「unknown capability: model」拒收；
3. **双击仓库根目录的 `一键体验-晨报卡.bat`**（或 `启动-晨报卡.cmd`）。

启动器 `tools/launch.py` 会自己找宿主、配模型通路、选空闲端口、放开场配乐，并在旁边挂一只
看门狗（界面万一卡成白屏会自动把卡片拉起来）。失败状态演示走 `一键体验-部分失败演示.bat`。

```powershell
# 开发者的老入口（路径按本机实际安装位置调整）：
powershell -ExecutionPolicy Bypass -File tools\stop.ps1     # 停
powershell -ExecutionPolicy Bypass -File tools\run.ps1      # 起（端口 8136）
powershell -ExecutionPolicy Bypass -File tools\shot.ps1 -Name 'my_shot.png'
python tools\brace.py                                       # main.splash 语法体检
```

## 贡献指南（欢迎继续改）

1. 改代码前先读 `进度交接_第45轮后.md` 的坑表（历轮大坑都在 `进度交接_*.md` 系列里）
2. 改 `main.splash` 的硬规矩：
   - 不用 `contains / slice / sort / map / filter`；保留字 `ok / me / scope / self / _` 不可作变量名
   - 数字拼串要先转文本再拼（`"" + n`）；拼接结果先 `let` 成变量再传参；`llm.chat` 的 `max_tokens <= 2048`
   - 渲染循环里不要再遍历同一数据源（会打断迭代，只出第一行）；JSON 缺字段要先取键再判空
   - `View{show_bg: true}` 的底色不渲染，要用 `RoundedView` / `SolidView`
   - makepad 的 `on_render` 子控件每帧重建，**必须显式 `.render()`**
   - 文件编码：`main.splash` 用 UTF-8 无 BOM + LF；**用脚本写文件要显式 `newline="\n"`**
   - 整块替换超过约 60 行时，用脚本按锚点切片（逐字符匹配会失败）
   - shader 里 `A.mix(B, t).mix(C, t)` 这类链式调用没有先例，拆成两条 `let`
3. 改完必须：`python tools\brace.py`（语法）→ `tools\run.ps1`（实跑）→ `tools\shot.ps1`（截图留证）
4. 每轮完成后：写一份 `项目复盘/日期_第N轮_主题.md`，并把交接文档更新到下一轮
5. 提交：`git add -A` → `git commit -m "第N轮：做了什么"` → `git push`

## 设计原则（为什么这么做）

- **先授权、再取数**：不批准不联网，取数范围与域名明示
- **不补齐条数**：部分来源失败就只展示成功来源，并列出失败项
- **可核验**：每条新闻都能看到来源、时间、原文链接
- **看得见的过程**：编辑部几个视角、各自用时多少秒，全部摆在明面上
