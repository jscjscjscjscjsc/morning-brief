# 第 37 轮 · 水面上的浏览器（Waterfront）

本轮把「顶部横幅」做成真正的浏览器式栏目标签，并顺手找出两个把界面画坏的老问题。
本机截图见 `round37/`（8 张，含四个栏目 + 自检状态）。

## 一、界面做了什么

1. **浏览器式栏目标签**：卡片最顶上一整条导航，五格等分：**头版 / 情报池 / 复盘 / 立场 / 读稿**。
   点哪一格哪一格亮 —— 亮的那格顶上一线天光、脚下一道金水线（就是「你正在这一页」）。
   连字都按内容走：情报池会写「情报池 24」、复盘写「复盘 3/3」、立场写更正与不一致的笔数。
   可见性只由 `sync_tabs()` 一个函数决定，它永远「五选一」，并且会自己把不成立的标签收回。
2. **三个新栏目**（全部读既有数据，零额外调用、零额外取数）：
   - 情报池：候选怎么上池、取数与兜底的规则、上限多少，一条条摊开；
   - 编辑部复盘：三位编辑的推荐与取舍理由、事实核查的内部对照、留痕入口；
   - 立场与更正：更正台账、口径不一致的笔数、本报写死的编辑方针（可被读者引用与追责）。
3. **读稿成为标签**：点开任意一条新闻，自动切到「读稿」那格；返回时回到头版。
   没有稿子时点它，会弹一句诚实的话，而不是切到一块空白 —— 这曾是最容易白屏的一条路。
4. **清晨太阳**：地平线太阳 + 晨海水面波纹（上一轮就写好了，但一直没画出来，见下）。
   天空加了标题柔光罩（太阳再亮，字也读得清）；海面安静下来，去掉了像铁丝网的 24px 刻度尺。
5. **水一样的材质**：划过是微澜、按下是从落点荡开的同心波纹；卡片、面板、标签格、主按钮
   全部换成同一套水面 SDF 着色器；整屏有极慢的横向折光在呼吸。
6. **守夜人**：每 0.5 秒重落一次可见性（幂等）。任何一条文案读不出来，只会少那一行字，
   底部弹一句「界面自检 · 有一段没读出来 · 第 N 次」的胶囊；界面不会再整块空掉。

## 二、顺手找出来的两个真问题（都从 card-host 日志里抓到）

- `[E] shader builtin atan requires 1 arg, got 2` —— 上一轮那套「晨曦放射霞光射线」用了
  两参数 `atan(y, x)`，这个宿主不认，**整个天空着色器编译失败**。界面因此一直是一块平夜色，
  太阳、霞光、晨海全都没画出来（用户说「前端渲染不够」，这就是原因）。已改成不用 atan 的写法。
- `[E] widget method render not found` —— 定时器里对 `ui.tab_rail` / `ui.water` 调 `.render()`，
  宿主不认；每 70 毫秒刷一行错。已改掉：水面自己吃 `draw_pass.time`，不需要外部推。
  现在整轮跑下来日志里 **0 条 [E]**。

## 三、怎么复现

```bash
python tools/round37_ui.py  [--dry]     # 标签栏 / 三个新页面 / 水底 / 守夜人 / 水面材质
python tools/round37_fix.py             # 标签栏挪到卡片顶上、太阳常驻、开机天亮
python tools/round37_fix2.py            # 去掉两参数 atan、修 render 调用与越界 box
python tools/round37_fix3.py            # 太阳落到地平线上方、标题柔光罩、海面安静
python tools/round37_fix4.py → fix5.py  # 自检提示做成底部胶囊
```
每个脚本都是「锚点切片 + assert 命中数」：同一个脚本重跑一次就是同一个结果，
锚点对不上就报错、绝不半途写盘。跑完再走 `tools/brace.py` / `audit_widgets.py` / `audit_globals.py`
三道体检（本轮全 PASS），最后 `python tools/portable_digest.py` 重算跨平台摘要。

## 五、两条容易踩的坑

- **摘要陷阱**：本地 `card-host --stamp`（也就是 `.dev/dev.sh run`）会把 manifest 里的
  `bundle_blake3` 改回 **Windows 版**。本地 `hub check` 因此会在「提交前」报 REFUSED —— 这是
  已知的上游缺陷（issue #75，修复 PR #79 未合并），不是本轮改坏了。规则：**每次本地跑完测试，
  提交前都要再跑一次 `python tools/portable_digest.py`**，让 manifest 回到 Linux/跨平台摘要，
  再用带补丁的 hub 复验。
- **不要跑 `hub stamp`**（Windows 版），它同样会把摘要写回 Windows 版。

本轮提交：`65ab400`（分支 `redesign/awwwards-ui`，未推送）。


## 六、看起来像「白屏」的第二种成因（本轮实测）

本地**不带 `--stamp`** 直接拉 `card-host.exe` 跑改版 bundle，会看到一块**纯空窗口**：

```
[E] card-host: refused: bundle digest 3a4cee25… does not match the manifest's 9a9242c9…: app morning-brief version 0.3.1
```

原因就是第五节那条摘要陷阱的另一面：提交用的 manifest 写的是**跨平台（Linux）摘要**，
而本机 `card-host` 按 Windows 路径算出来的摘要不一样 → 卡片被**拒收** → 窗口是空的。
这和「用着用着白屏、只能退出重开」不是同一个毛病（被拒收的话每次重开都还是空），
但排查时值得先看一眼宿主日志里有没有 `refused`：

- 双击 `启动-晨报卡.cmd` / `python tools/launch.py`：`octo run` 会自动带 `--stamp`（见 tools/octo 第 338 行），没问题；
- 手工拉 `card-host.exe`：记得补上 `--stamp`；
- 提交前：再跑一次 `python tools/portable_digest.py` 把摘要还原成跨平台版。
